# 窑炉（Kiln）

窑炉是 Minecraft 26.2 / NeoForge 统一模组 `ww_hfas` 中的功能方块，方块和物品 ID 均为 `ww_hfas:kiln`。目前复用原版熔炉四向模型、点燃模型、界面贴图、烟雾／火焰粒子和燃烧声，显示名称为「窑炉」。后续可以独立替换模型。

## 获取与合成

位于创造模式「原野之风」分页，沿用本项目所有模组物品集中分页的设置。最大堆叠为 64。

```mcfunction
/give @s ww_hfas:kiln
/setblock ~ ~ ~ ww_hfas:kiln[facing=north]
```

工作台配方如下，红砖使用 `minecraft:brick`，泥坯使用 `minecraft:packed_mud`：

| 左 | 中 | 右 |
| --- | --- | --- |
| 空 | 红砖 | 空 |
| 红砖 | 熔炉 | 红砖 |
| 泥坯 | 泥坯 | 泥坯 |

合成产出 1 个窑炉，获取熔炉后解锁该合成配方。

## 烧炼与燃料

窑炉读取当前世界的熔炉配方，输出数量、物品组件和经验值沿用该配方，每次固定烧炼 **100 游戏刻**，在 20 TPS 下为 5 秒、每分钟 12 件。砂子、黏土球、圆石、石头、仙人掌、海泡菜、木头、湿海绵及符合条件的其他材料可用。按需求中“矿物、金属工具、武器和盔甲以外”的范围，具有普通熔炉配方的食物也可以烧炼；不会为原本没有配方的物品新增烧炼产物。

原料限制由以下规则共同决定：

- `ww_hfas:kiln_excluded` 排除标签默认包含公共的矿石、粗金属、锭、粒、宝石标签。
- 具有高炉配方的原料排除，覆盖原版矿物和金属装备回收。
- 可损耗耐久的物品若烧炼产物属于 `ww_hfas:kiln_metal_outputs`（默认锭、粒），也会排除。

上方输入槽和顶部漏斗拒绝不符合条件的物品。即使使用指令强行写入不合格原料也不会烧炼或点火。数据包可扩展这两个物品标签；已有配方随世界配方加载／重载生效。

使用普通熔炉燃料及燃烧时长，因此一块煤提供 1600 刻燃烧时间，连续烧炼最多 16 件普通单件产物。持续燃烧期间即使缺料或输出堵塞也会消耗剩余燃料。冷炉无有效原料、无空间容纳完整产物时不会消耗新的燃料。移除燃料导致熄火时，未完成进度按原版速度回退；更换不同原料会重新计时。

岩浆桶作为燃料会返还铁桶；燃烧期间烧炼湿海绵且燃料槽内存在铁桶时，会得到水桶。燃料容器返还遵循原版及 NeoForge 的 crafting remainder 规则。

## 容器、自动化与经验

界面上方为烧炼槽、下方为燃料槽、右侧为成品槽，各槽遵循物品自身的最大堆叠限制，支持 Shift 转移。界面使用原版熔炉背景与进度图案，当前不附带配方书。

| 漏斗位置 | 行为 |
| --- | --- |
| 上方 | 将可用原料放入烧炼槽 |
| 侧面 | 将燃料放入燃料槽 |
| 下方 | 先取成品，再取燃料槽中的铁桶／水桶 |

也提供 NeoForge 分面物品传输能力。红石比较器统计全部三个槽位的占用比例，空容器为 0，全部装满为 15。

经验按成功完成的原版配方累计并保存。漏斗取出成品保留经验；玩家从成品槽拿取或 Shift 取出时释放此前存储的经验并清空记录。破坏窑炉会掉落内容物并释放剩余经验。物品、燃料时间、进度、配方经验记录、名称及锁定条件均持久化。

## 方块属性与采集

硬度 3.5，爆炸抗性 3.5。完整实心方块，可使生物窒息、传导红石并压断占位的红石线；不能被活塞推拉。音符盒乐器为底鼓，地图颜色暂用石头色。未燃烧时不发光，燃烧时亮度为 13。

用木镐或更好的镐可采集窑炉本体，其他工具不能获得本体；容器内物品和存储经验仍按破坏流程释放。原材料可再生，因此可通过合成持续获得。

## 命名与锁定

铁砧重命名窑炉物品后再放置，界面显示该名称；用正确工具采集后名称保留。也可用指令修改已放置的方块实体（将坐标替换为目标位置）：

```mcfunction
/data merge block ~ ~ ~ {CustomName:"建筑窑炉"}
/data merge block ~ ~ ~ {lock:{items:"minecraft:brick"}}
/data remove block ~ ~ ~ lock
```

上例将锁设为手持红砖才能打开；锁使用当前原版 `lock` 物品谓词格式。旁观模式沿用原版访问规则。锁限制玩家开启界面，不阻止漏斗。

## 村庄生成

原版沙漠、平原、热带草原、积雪平原（两种）和针叶林共六种石匠屋模板，在通过村庄结构池生成时增加一个窑炉。窑炉朝向随房屋旋转，保留原有切石机和石匠职业工作站。只影响后续新生成的建筑，不扫描或修改存档内已有石匠屋。

实现按模板 ID 和已核对的局部位置附加结构处理器，不覆盖原版结构池 JSON 或模板文件。如果数据包在目标位置放了不同方块，会跳过该位置，避免覆盖改造后的箱子或工作站。直接 `/place template` 放置原版模板不会触发结构池附加处理。

## 验证与代码入口

`KilnGameTests` 提供 `kiln`、`kiln_inventory`、`kiln_villages` 三组服务器游戏测试，涵盖配方、100 刻边界、物品筛选、燃料与保存、容器自动化、经验、锁定、比较器、掉落及六种石匠屋四个旋转方向的结构池放置。客户端界面已编译并注册，尚未进行人工游戏内界面检查。

主要实现位于 `block/KilnBlock.java`、`block/entity/KilnBlockEntity.java`、`menu/KilnMenu.java`、`client/KilnScreen.java`、`recipe/KilnRecipes.java`、`worldgen/MasonKilnProcessor.java`。数据生成器维护合成配方、战利品表、挖掘标签、模型引用与中英文名称；源码资源包含无需运行数据生成时的备用文件。
