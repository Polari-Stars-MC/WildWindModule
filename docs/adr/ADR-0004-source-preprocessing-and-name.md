# ADR-0004 — 改用源码预处理作为版本差异主导机制（取代 ADR-0003 的方案 B）

- 状态：已接受（取代 [ADR-0003](./ADR-0003-imp-middle-layer-apt.md) 中"纯 APT"的机制选择）
- 关联：[ADR-0003](./ADR-0003-imp-middle-layer-apt.md) · [ARCHITECTURE.md](../ARCHITECTURE.md) §3.4 · [AGENTS.md](../../AGENTS.md)

## 背景

ADR-0003 选的是方案 B（注解处理器生成适配层）。落地后发现它与实际需求不匹配：

1. **需求是"所有版本写在同一个类里"**，不适用的实现要被真正抹掉。APT 只能生成新类，
   **删不掉既有成员**——两套分叉 API（如 1.21 的 `ResourceLocation` 与 26.x 的 `Identifier`）
   会同时参与编译，单类方案根本无法成立。
2. **需要 `@Name` 改名**：源码里用顺手名字书写、打包时改成目标版本真实名字。APT 改不了既有声明。
3. **需要对 import 做版本处理**（后被"FQN 约定"规避，见决策 §3）。

ADR-0003 里把方案 A（源码预处理）标为"暂缓"，理由是成本高。但在"单类 + 全版本"的目标下，
A 不是可选项而是唯一路径。

## 决策

### 1. 主导机制改为源码预处理

新增 `SourcePreprocessor`（在 `imp-processor` 模块内，基于 JavaParser）：

- 删除目标版本不存在的成员（`@Since` / `@Until`，支持 `until` 区间与 `exclude` 空洞）；
- 应用 `@Name`：声明与调用点一起改名；
- 应用外部改名表 `gradle/imp-renames.txt`（MC 自身跨版本改名）；
- 输出 `build/preprocessed/java`，由 `preprocessImpSources` 任务驱动，`compileJava` 依赖它。

APT（`ImpManifest`）保留但降级：只服务"同一成员在某版本多/少一个参数"这种参数差异的运行时分派。

### 2. 新增 `@Name`

`@Target({TYPE, METHOD, FIELD, CONSTRUCTOR})`，`SOURCE` 保留策略。打在声明上即表示
"产物里叫这个名字"，处理器同时改写声明与调用点。

歧义处理：同一旧名映射到不同新名时**直接报错**，不做猜测。

### 3. import 不做门控，改用 FQN 约定

Java 语法不允许注解修饰 `import`（JLS：注解只能修饰声明）。原本可选的三种方案里选了
"版本分叉的类一律不 import，成员内用全限定名"：

- 被裁掉的成员连带其类型引用一起消失，无需条件编译；
- 零工具成本，不需要解析 import 块；
- 代价：方法签名里会出现 `net.minecraft.resources.Identifier` 这种长名字。

### 4. 退役按族分目录的实现类

上一轮试点的 `imp/src/family/{1.20,1.21,26.x}` + `FamilyBridge` 已删除，跨族差异全部收敛进单类的
`@Since`/`@Until`/`@Name` 组合。版本族概念仅保留用于**依赖与工具链选择**
（1.20.4/20.4.253/Java17、1.21.1/21.1.209/Java21、26.2/26.2.0.75/Java25）。

## 后果

- ✅ 真正做到"一个类容纳所有版本"，不适用的代码不进产物（jar 里只有当前版本的实现）。
- ✅ `@Name` 让源码可用稳定名字书写，跨版本改名由构建处理。
- ✅ 裁剪发生在 javac 之前，"引用了被裁成员"会变成编译错误，暴露得早。
- ⚠️ 单类形态下 IDE 只能对一个版本显示为绿，其它版本的引用会标红——这是共处一个文件的必然代价。
- ⚠️ `@Name` 与外部改名表都按**简单名**匹配，不做符号解析；同名不同类会被一起改，加规则前必须确认无歧义。
- ⚠️ 解析器成为构建依赖（JavaParser），预处理失败会阻塞整个模块构建。
- 📌 `ImpManifest` 与 `@ParamSince` 的重载分派仍保留；成员级差异不应再用 `if (ImpManifest.HAS_X)` 表达。

## 替代方案及其否决理由

| 方案 | 否决理由 |
|---|---|
| 继续纯 APT（ADR-0003 方案 B） | 删不掉成员、改不了名字，无法实现单类多版本 |
| 按族分目录（上一轮试点） | 与"所有东西放一个类"的目标冲突；已退役 |
| 字节码后处理（ADR-0003 方案 C） | 参数移除需字节码级副作用分析，与 reobf/mixin 叠加不可调试 |
| 注解修饰 import | Java 语法不允许，物理上不可行 |
